# ML API Contract для gpb-reviewer

## 📋 Обзор

Этот документ описывает контракт API для интеграции ML модели анализа тональности и классификации тем отзывов в дашборд gpb-reviewer.

## 🔌 Эндпоинт

```
POST /api/analyze
Content-Type: application/json
```

## 📥 Входной формат (Request)

Организаторы ЛЦТ Хакатона будут отправлять JSON с массивом из ~250 отзывов:

```json
{
  "reviews": [
    {
      "id": "123",
      "text": "Очень удобно пользоваться дебетовой картой, но ипотека в приложении не работает"
    },
    {
      "id": "124", 
      "text": "Служба поддержки отвечает слишком долго"
    },
    {
      "id": "125",
      "text": "Отличные условия автокредита, рекомендую всем!"
    }
  ]
}
```

### Схема входных данных:
- `reviews` (array, required) - массив отзывов
  - `id` (string, required) - уникальный идентификатор отзыва
  - `text` (string, required) - текст отзыва для анализа

## 📤 Выходной формат (Response)

ML модель должна вернуть JSON с результатами анализа:

```json
{
  "results": [
    {
      "id": "123",
      "topics": ["debit_cards", "mortgage"],
      "sentiments": ["positive", "negative"]
    },
    {
      "id": "124",
      "topics": ["support"],
      "sentiments": ["negative"]
    },
    {
      "id": "125", 
      "topics": ["auto_credit"],
      "sentiments": ["positive"]
    }
  ],
  "errors": []
}
```

### Схема выходных данных:
- `results` (array, required) - массив результатов анализа
  - `id` (string, required) - соответствует входному id отзыва
  - `topics` (array, required) - массив тем/продуктов, обнаруженных в отзыве
  - `sentiments` (array, required) - массив тональностей, соответствующих темам
- `errors` (array, optional) - массив ошибок обработки (если есть)

## 🏷️ Справочники

### Поддерживаемые темы (topics):
- `credit_cards` - кредитные карты
- `debit_cards` - дебетовые карты  
- `mortgage` - ипотека
- `auto_credit` - автокредиты
- `deposits` - депозиты/вклады
- `support` - служба поддержки
- `mobile_app` - мобильное приложение
- `transfers` - переводы
- `cash_withdrawal` - снятие наличных
- `online_banking` - интернет-банк
- `other` - прочее

### Поддерживаемые тональности (sentiments):
- `positive` - позитивная тональность
- `negative` - негативная тональность  
- `neutral` - нейтральная тональность

## ⚖️ Правила выравнивания

**Важно:** Количество элементов в массивах `topics` и `sentiments` должно совпадать для каждого отзыва.

Если в отзыве несколько тем:
- Тональности должны дублироваться в том же порядке, что и темы
- Каждой теме соответствует своя тональность

### Пример с несколькими темами:

```json
{
  "id": "123",
  "topics": ["debit_cards", "mortgage", "support"], 
  "sentiments": ["positive", "negative", "negative"]
}
```

## 🚨 Обработка ошибок

Если ML модель не может распознать тему или тональность:

### Допустимые fallback значения:
- **Темы:** `"none"`, `"прочее"`, `"other"`
- **Тональности:** `"none"`, `false`, `"neutral"`

### Пример обработки ошибки:

```json
{
  "id": "problematic_review",
  "topics": ["none"],
  "sentiments": ["neutral"]
}
```

## ⏱️ Производительность

### Ограничения:
- **Время ответа:** максимум 3 минуты на обработку ~250 отзывов
- **Таймаут:** если модель не отвечает за 3 минуты, запрос будет прерван
- **Объем данных:** ~250 отзывов за один запрос

### HTTP статус коды:
- `200 OK` - успешная обработка
- `400 Bad Request` - некорректный формат входных данных
- `408 Request Timeout` - превышено время ожидания 3 минуты
- `500 Internal Server Error` - ошибка ML модели

## 🧪 Тестирование

### Тестовый запрос:

```bash
curl -X POST http://localhost:5000/api/analyze \
  -H "Content-Type: application/json" \
  -d '{
    "reviews": [
      {
        "id": "test_1",
        "text": "Отличная дебетовая карта, очень доволен"
      }
    ]
  }'
```

### Ожидаемый ответ:

```json
{
  "results": [
    {
      "id": "test_1", 
      "topics": ["debit_cards"],
      "sentiments": ["positive"]
    }
  ],
  "errors": []
}
```

## 📊 Интеграция с дашбордом

После успешной интеграции ML API:

1. **Дашборд автоматически получит** актуальные данные по темам и тональности
2. **Графики обновятся** с реальными результатами ML анализа
3. **Фильтрация по продуктам** будет работать на основе распознанных тем
4. **Статистика тональности** отобразит реальные результаты модели
